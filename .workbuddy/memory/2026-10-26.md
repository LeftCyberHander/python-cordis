# 2026-10-26

## cordis_py：修复作用域/调用方重绑，并补业务插件教程

### 修复的核心问题
根因是 Python 版用 `__getattr__` 模拟 JS 的 Proxy，但漏了「调用方重绑」这一层：
- `Service.__init__` 调 `ctx.reflect.provide(...)` 没传 `caller`，所有服务注册到根
  → `isolate` 完全失效，第二个工作区撞名（`service "docs" has been registered at <root>`）。
- `ctx.get` / `accessor` / `mixin` / `on` 都没把调用方上下文传下去。
- `reflect` / `registry` / `events` / `logger` 是实例属性，普通属性查找绕过 `__getattr__`，
  需要在 `Context.__getattribute__` 里对这四个名字做 `get_traceable` 重绑。
- 内置服务的 tracker 是普通 dict（`{"property": "ctx"}`），改成 `Tracker` 实例。
- 新增 `ServiceView`：方法体里 `self.ctx` 指向调用方，且写属性透写回原实例。

### 其他修复（按 docs/CORRECTNESS.md 的裁决：参考实现的缺陷不算正确性依据）
- `parallel` 上报 `parallel`；`is_bailed` 改为「非 None/False 即中止」。
- `LoggerService.exporter` 注册时捕获序号；`_dispatch` 的 cause 分支不再 return。
- 事件名映射改为 `_HookMap`（验证器要求 `_hooks._store`）。
- `waterfall` 每层独立续体、恰好推进一次。
- `Fiber.update` 任何状态都返回 awaitable；own hooks 直接跑，不走全局 router。
- `_run_disposable` 用 `is None` 判空，不再吞 `0/''/False`。
- `_spawn` / `_drive_catch`：fire-and-forget 的协程必须显式调度；`await_` 会 drain `_pending`。
- `registry.resolve` 支持 `{inject, apply}` dict；`plugin_attr` 统一取元数据。
- `Context.__contains__` 覆盖类成员；`intercept` 改为链式层（`__cordis_parent_intercept__`）。
- 移除 `Context.__init__` 里的 `fiber._disposables.clear()`；新增 `_logger_service` 诊断句柄。
- `DisposableList.unshift`。

### 新增文档
- `docs/PLUGIN_GUIDE.md`：业务插件开发教程（心智模型 / provide / inject / isolate /
  effect / 事件 / 两种插件形态 / 配置 / 装配 / 测试 / 常见错误）。
- 重要语义：Service 方法里的 `self.ctx` 是**调用方**，跨插件调用时调用方也要 inject；
  推荐在 `__init__` 缓存依赖。事件是进程级、不隔离。
- 测试坑：整个场景必须放在同一个事件循环里，跨 `asyncio.run` 会 `CancelledError`。
